# NeatPaste v0.6.0 design

The interface is a compact macOS utility. Its [official references](REFERENCES.md) are Apple’s material guidance and AirDrop transfer dialog. A short toolbar, file information, one format popup and a blue action button replace the previous illustration, slogan, format-card grid and full-width call to action. Completion keeps the file context and makes Show in Finder the primary action. English and Chinese use system fonts, 13-point toolbar text and 11–12-point controls and supporting text.

The resting window is 208 × 48 logical points including six-point transparent margins: the visible capsule is 196 × 36 with an 18-point radius. Expanded windows are 332 points wide with a 22-point surface radius. Native layout presets are `empty` (228 high), `file` (272), `batch` (352), `settings` (398), `animation` (360) and `animationbatch` (432). Motion batches use the taller presets for GIF options. Successful or partially successful batches return to ordinary file or batch height; an all-failed batch keeps the animation controls available for retry. The last content layout survives collapse and settings visits. A top-center anchor persists across resizing, edge clamping and collapse. Larger queues and long warnings scroll; they do not grow without bounds. Frontend layout requests are serialized and coalesced to the latest requested preset; unchanged native presets do not resize or emit another expanded event.

macOS uses a reusable NSVisualEffectView with BehindWindow blending, Active state and Popover material clipped inside the same six-point margin. The web content adds a neutral translucent tint and opaque text. This is standard macOS material, not a custom Liquid Glass renderer. Browser preview uses CSS backdrop blur over an original CSS background. New installations follow system appearance; explicit previous light/dark choices are retained. Reduced-motion and increased-contrast styles are supported, with an opaque fallback for reduced transparency. No idle animation, remote font, raster hero, polling process or new dependency was added.

Drag-enter changes feedback without resizing the target; dropping expands it. The left tray icon is the window drag surface. Escape closes settings first, then collapses the window. A native picker or settings session prevents focus-loss collapse. Format selection retains keyboard focus, closing settings returns it to the settings control, and ordinary rerenders preserve scroll positions. These host interactions require native QA; browser previews alone do not establish them.

Optional conversion on drop requires opt-in, a remembered supported format for the file family, at least one new registered file ID and no invalid entries. The `motion` family remembers its output format independently from still images. GIF options are local preferences, defaulting to a 480-pixel maximum long edge, 15 fps and looping on. Removing files or opening an existing batch must not start another conversion. After a completed batch, the next nonempty drop or picker selection replaces that queue; an empty or cancelled picker retains existing results.

The format matrix follows actual system codecs. WebP is decode-only. Still-image inputs, including existing GIF files, retain the first-frame conversion path and produce static GIFs. MOV/MP4 inputs use AVFoundation for local frame decoding and ImageIO for animated GIF encoding, without a bundled video runtime. The options are 320/480/640 pixels on the long edge, 10/15/20 fps and looping on/off. Sources are not enlarged. GIF contains no audio; its limited palette and centisecond frame timing may differ from the source video. Inputs over 100 MiB or 15 seconds are rejected rather than trimmed.

Live Photo support is an explicit exported-file workflow: a HEIC/HEIF/JPG/JPEG and MOV supplied in the same batch, in the same directory, with the same filename stem, become one queue item. The host pairs supplied paths; it neither scans for adjacent files nor reads the Photos library. This filename association does not validate Apple's asset identifiers. The conversion uses the MOV component and keeps both originals. A still file alone remains static, and direct Photos dragging does not guarantee that motion is provided. Photos effects are outside the workflow. Synthetic-video QA must not be presented as a physical iPhone/Photos export test.

Video metadata loading has a 15-second deadline and forbids external asset references. GIF conversion requires at least 0.04 seconds of video and no more than 40 megapixels per source frame. It retains no explicit frame array, uses a per-frame autorelease pool, and limits work to 300 frames / 125 million output pixels. A bounded data sink rejects output over 50 MiB. Centisecond frame boundaries distribute timing rounding, including the final remainder; loop-off omits the GIF loop extension. The host's 120-second process timeout also applies. These limits do not establish a peak-memory guarantee for AVFoundation or ImageIO.

PDF raster export is page 1 at 144 dpi; plain text export reflows embedded text without OCR or original layout. PDF-to-Word adds internal PNG media and DrawingML relationships, mixing editable line blocks with rendered image regions. Complex pages use an explicit full-page-image fallback; text inside those images is not editable. Images never use external relationships. Visible non-link annotations must be flattened before conversion. CSV/TSV/JSON preserve text cells without inferred headers or numeric types. Relevant caveats appear before conversion and helper warnings remain visible on result rows.

Tauri/Rust owns native file grants, queue IDs, output paths and safe publication. A bounded Swift helper uses system frameworks per conversion and then exits. Outputs publish atomically through macOS `renamex_np(RENAME_EXCL)`, numbering collisions. Originals and existing exports are preserved; symlink export folders are rejected. No renderer filesystem permission, remote converter, folder watcher or office runtime is added.

Limits are documented in the README. Window size is not a memory measurement; current verification and measurement boundaries belong in [VALIDATION.md](VALIDATION.md).
